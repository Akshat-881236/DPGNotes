Platform Architecture & System Topography

Complete architectural blueprint of DPGNotes: microservices ecosystem, client-server topology, edge routing, caching layers, and high-availability patterns.

1.1 Enterprise System Overview & Core Mission

Core

DPGNotes is engineered as an enterprise-grade academic knowledge exchange platform serving university students, educators, and independent learners. The platform bridges the gap between syllabus lectures and real-world exam requirements across 8 core disciplines: Sessional Exams (SE), Sample Papers (SP), University Exams (UE), Event Materials (EV), Tutorial & Notes (T&N), Interview Questions (IQ), Aptitude & Logical Reasoning (A&LR), and Placement Papers (PQ).

Architectural Mission Statement
Democratize high-yield academic documentation with zero paywalls, complete attribution to verified contributors, and verifiable cryptographic integrity.

Visit the live platform at DPGNotes Homepage or inspect verified contributions at Contributor Dashboard.

1.2 Edge Network & Global Distribution Model

Network

The static frontend is deployed via Google Firebase Hosting, backed by Google's Fastly-powered global Content Delivery Network (CDN) Points of Presence (PoPs). All assets are served over HTTP/2 and HTTP/3 with automatic TLS certificate lifecycle management and Gzip/Brotli compression.

1.3 Stateless Microservices & Node.js Cluster

Backend

The backend operates as an Express.js service hosted on Render (Frankfurt / Oregon cloud regions). The architecture follows a shared-nothing, 12-factor stateless design, allowing horizontal scalability behind Render's native reverse-proxy load balancer.

  • Stateless session verification via signed JSON Web Tokens (JWT) and Firebase Admin SDK credentials.
  • Sub-second cold-start recovery with automated keep-alive telemetry pings.
  • Encrypted proprietary logic running entirely in-memory via AES-256 authenticated decryption.

1.4 Cloud Firestore Real-Time NoSQL Backbone

Database

Persistent storage is powered by Google Cloud Firestore in Datastore mode. Documents are indexed automatically for single-field queries, while composite indexes accelerate multi-parameter filtering across academic semesters, subject tags, and screentime telemetry.
