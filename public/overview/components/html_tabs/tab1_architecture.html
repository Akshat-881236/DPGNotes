2. Component Hierarchy, ER Diagram & Core Data Flows

This subsystem is architected into four decoupled engineering pillars to guarantee horizontal scale-out and continuous service availability:

  • 1. Presentation Layer (Global Client SPA): Deployed globally across Google Firebase Hosting edge Points of Presence (PoPs), serving static assets over HTTP/3 with automatic Brotli compression, edge SSL termination, and immutable browser caching.
  • 2. Edge Reverse Proxy Gateway: Edge rewrite rules intercept incoming /api/** traffic and proxy requests directly to containerized backend clusters, forwarding client IP headers (x-forwarded-for) while cloaking origin server infrastructure.
  • 3. Stateless Compute Microservices: A dual Node.js / Express and Python FastAPI cluster hosted on Render. State is externalized to persistent datastores, enabling seamless horizontal scale-out behind native reverse-proxy load balancers.
  • 4. Distributed Persistence Backbone: Google Cloud Firestore multi-region clusters (eur3) providing automatic sharding, real-time snapshot synchronization (onSnapshot), and sub-50ms query execution.

3. Step-by-Step Production Implementation Guide

Follow the practical engineering roadmap to configure, implement, and deploy this subsystem:

  1. Configure firebase.json with selective edge rewrites mapping all /api/** calls directly to the Render microservice while serving static HTML/JS/CSS assets with immutable cache-control headers (max-age=31536000).
  2. Bootstrap the Node.js / Express application setting app.set('trust proxy', 1) to accurately capture remote client IP addresses behind multi-tier load balancers.
  3. Attach helmet and cors middleware configuring strict origin whitelisting allowing only official production domains (https://dpgnotes.web.app).
  4. Implement non-blocking health check probes (/api/health) queried every 10 minutes by micro-daemon pings to prevent container sleep cycles on containerized cloud tiers.
  5. Initialize Google Cloud Firestore multi-region drivers with atomic counter transactions to prevent race conditions during high-concurrency student access periods.

// Module 1: Production 3-Tier Express Gateway & Health Monitor
const express = require('express');
const helmet = require('helmet');
const cors = require('cors');

const app = express();
app.set('trust proxy', 1);
app.use(helmet({ contentSecurityPolicy: false }));

// Enforce strict academic security boundary
app.use(cors({
  origin: ['https://dpgnotes.web.app', 'https://dpgnotes.firebaseapp.com'],
  methods: ['GET', 'POST', 'PUT', 'DELETE'],
  credentials: true
}));

app.get('/api/health', (req, res) => {
  res.status(200).json({
    status: 'ONLINE',
    uptimeSeconds: Math.floor(process.uptime()),
    timestamp: new Date().toISOString(),
    service: 'DPGNotes-Core-Gateway',
    clusterRegion: 'eu-west-1'
  });
});

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => {
  console.log(`[DPG-CORE] Microservice operational on port ${PORT}`);
});
