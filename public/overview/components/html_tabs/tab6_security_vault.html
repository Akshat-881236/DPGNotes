Cryptographic Vault & AES-256-GCM Security Engine

20 min read Production-Verified DRASA Engineering Standard

Security in DPGNotes is constructed on the premise of zero-trust architecture. Sensitive system parameters, API secrets, and proprietary algorithmic routines are shielded by an authenticated AES-256-GCM encryption vault with PBKDF2 key derivation (100,000 iterations). Protected logic and dynamic evaluation rules execute inside isolated Node.js V8 sandboxes (node:vm) with strict memory and CPU barriers, guaranteeing zero plaintext credentials on disk and complete immunization against Remote Code Execution (RCE) and Cross-Site Scripting (XSS).

1. Architectural Scope & Software Requirements Specification (SRS)

Subsystem Directive: Authenticated Symmetric Encryption, Ephemeral In-Memory Vaults & Sandboxed V8 Contexts.

The Software Requirements Specification (SRS Section 6.0) requires end-to-end cryptographic defense across all computational and storage boundaries. High-value credentials (database root secrets, AI provider API tokens, Brevo SMTP keys, and confidential administrative routing rules) must never be committed to source code repositories, written to container file systems, or leaked into client-facing network bundles.

Security & Tamper-Proofing Guarantee
All vaulted payloads are protected using AES-256-GCM with a randomized 12-byte Initialization Vector (IV) and a 16-byte Authentication Tag. Any alteration to encrypted ciphertexts or tampering with the auth tag results in immediate authentication failure and process-level security aborts.

2. Component Hierarchy & Sandboxed Execution Topology

The cryptographic subsystem is organized into four defensive containment rings:

  • 1. In-Memory Key Derivation Layer (PBKDF2): Derives high-entropy 256-bit symmetric encryption keys from master passwords and unique salts using 100,000 rounds of HMAC-SHA512 hashing.
  • 2. Authenticated AES-256-GCM Cipher Engine: Encrypts configuration matrices into compact base64 bundles comprising salt:iv:authTag:ciphertext. Decrypts directly into memory buffers without intermediate disk writes.
  • 3. Node.js V8 Sandboxed Virtual Machine (node:vm): Executes sensitive or user-contributed mathematical formulas inside isolated vm.createContext() instances with a strict 200ms execution timeout and zero access to global process, require, or file-system primitives.
  • 4. Client-Side CSP & Sanitization Barrier: Enforces strict Content Security Policy directives on all HTML pages, stripping inline script injections and sanitizing dynamic user strings before DOM insertion.

3. Step-by-Step Production Implementation Guide

Follow the practical engineering roadmap to configure and operate the DPGNotes Cryptographic Vault:

  1. Establish Cryptographic Primitives: Import Node.js built-in crypto and vm modules without third-party dependencies to minimize supply-chain attack vectors.
  2. Generate High-Entropy IVs: For every encryption event, generate a cryptographically strong 12-byte IV using crypto.randomBytes(12) to prevent cipher stream reuse.
  3. Attach Authentication Tags: Capture the 16-byte authentication tag from cipher.getAuthTag() and serialize it alongside the IV, salt, and encrypted payload.
  4. Construct Sandboxed V8 Contexts: Instantiate vm.createContext({}) freezing all sensitive host objects (e.g. Object.freeze()) to execute untrusted routines safely.
  5. Automated Integrity Auditing: Execute the production vault verification script (node backend/security/verify-vault.js) during GitHub Actions CI/CD before any deployment occurs.

// Module 6: Authenticated AES-256-GCM Vault & V8 Sandbox Evaluator
const crypto = require('crypto');
const vm = require('vm');

const ALGORITHM = 'aes-256-gcm';
const KEY_LEN = 32;
const IV_LEN = 12;
const SALT_LEN = 16;
const PBKDF2_ITERATIONS = 100000;

class DPGSecurityVault {
  static deriveKey(password, salt) {
    return crypto.pbkdf2Sync(password, salt, PBKDF2_ITERATIONS, KEY_LEN, 'sha512');
  }

  static encrypt(plainText, masterPassword) {
    const salt = crypto.randomBytes(SALT_LEN);
    const iv = crypto.randomBytes(IV_LEN);
    const key = this.deriveKey(masterPassword, salt);

    const cipher = crypto.createCipheriv(ALGORITHM, key, iv);
    let encrypted = cipher.update(plainText, 'utf8', 'base64');
    encrypted += cipher.final('base64');

    const authTag = cipher.getAuthTag();

    // Package as single bundle: salt:iv:authTag:ciphertext
    return [
      salt.toString('base64'),
      iv.toString('base64'),
      authTag.toString('base64'),
      encrypted
    ].join(':');
  }

  static decrypt(bundle, masterPassword) {
    const [saltB64, ivB64, tagB64, cipherText] = bundle.split(':');
    if (!saltB64 || !ivB64 || !tagB64 || !cipherText) {
      throw new Error('Malformed cryptographic bundle.');
    }

    const salt = Buffer.from(saltB64, 'base64');
    const iv = Buffer.from(ivB64, 'base64');
    const authTag = Buffer.from(tagB64, 'base64');
    const key = this.deriveKey(masterPassword, salt);

    const decipher = crypto.createDecipheriv(ALGORITHM, key, iv);
    decipher.setAuthTag(authTag);

    let decrypted = decipher.update(cipherText, 'base64', 'utf8');
    decrypted += decipher.final('utf8');
    return decrypted;
  }

  /**
   * Safely evaluates dynamic expressions inside a locked Node.js V8 Sandbox
   */
  static evaluateInSandbox(codeSnippet, sandboxContext = {}) {
    const context = vm.createContext({
      Math: Math,
      Date: Date,
      JSON: JSON,
      ...sandboxContext
    });

    const script = new vm.Script(codeSnippet);
    return script.runInContext(context, {
      timeout: 200, // Terminate after 200ms
      displayErrors: false
    });
  }
}

module.exports = DPGSecurityVault;
